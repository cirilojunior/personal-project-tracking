     Plano — Tracker de Projetos de Consultoria (Discovery + Delivery)

     Contexto

     Consultor freelancer (engenheiro de software) quer um sistema pessoal para
     acompanhar os projetos em que trabalha:
     - Discovery: cadastrar projeto (tema/área de negócio), cliente, requisitos
       funcionais/não funcionais e tarefas de alto nível.
     - Delivery: board Kanban de itens de trabalho (tarefa + subtarefas) com 9
       status, marcação de Impedido e Aging WIP.
     - Dashboard com visão geral.

     Decisões tomadas com o usuário: frontend Next.js + shadcn/ui (pt-BR)
     separado; backend Spring Boot (última estável, 4.x) + Java 25 LTS + Maven;
     banco H2 em memória. Diretório C:\Users\clxj\ProjetosClaudeCode\teste1 está
     vazio e não é repositório git.

     Ambiente atual: só há JDK 21, git 2.52; não há Node nem Maven.
     Pré-requisitos: instalar JDK 25 (winget install 
     EclipseAdoptium.Temurin.25.JDK) e Node 24 LTS (winget install 
     OpenJS.NodeJS.LTS). Maven via wrapper (mvnw), sem instalação global.

     Estrutura do repositório (monorepo)

     teste1/
       backend/    Spring Boot (Maven wrapper)
       frontend/   Next.js (App Router, TS)
       README.md   .gitignore   CLAUDE.md
     git init na raiz, branch main, commits por fase.

     Modelo de domínio

     - Cliente: nome, empresa, e-mail, telefone, observações.
     - Projeto: nome, tema/área de negócio, descrição, cliente (FK), status
       (DISCOVERY, EM_ANDAMENTO, PAUSADO, CONCLUIDO), datas de criação/início.
     - Requisito (Discovery): projeto, código (ex. RF-001/RNF-001, gerado),
       título, descrição, tipo (FUNCIONAL, NAO_FUNCIONAL), categoria NFR
       opcional (desempenho, segurança, usabilidade…), prioridade MoSCoW, status
       (RASCUNHO, VALIDADO, APROVADO, DESCARTADO).
     - TarefaDiscovery (alto nível): projeto, título, descrição, prioridade,
       status (A_FAZER, EM_ANDAMENTO, CONCLUIDA), requisitos relacionados (N:N).
       Ação "Enviar para Delivery" cria um ItemTrabalho em SELECIONADO
       vinculado.
     - ItemTrabalho (Delivery): projeto, título, descrição, prioridade, status
       (SELECIONADO, EM_REFINAMENTO, REFINADO, EM_IMPLEMENTACAO, IMPLEMENTADO,
       EM_TESTES, TESTADO, AGUARDANDO_PLANEJAMENTO_IMPLANTACAO, CONCLUIDO),
       ordem na coluna, impedido + motivoImpedimento + impedidoDesde, inicioWip,
       concluidoEm, tarefa de origem (opcional).
     - SubTarefa: item de trabalho, título, concluída, ordem.
     - HistoricoStatus: item, de → para, data/hora (base para aging, tempo por
       coluna e futuras métricas de lead/cycle time).

     Regra de Aging WIP (premissa, ajustável): o relógio inicia na primeira
     saída de SELECIONADO (ponto de compromisso) e para em CONCLUIDO. Idade =
     dias desde inicioWip. No card: badge com dias e cor (verde < 5d, amarelo
     5–10d, vermelho > 10d — limites em configuração). Itens impedidos ficam com
     destaque vermelho e mostram há quanto tempo estão impedidos.

     Backend (backend/)

     - Gerado via start.spring.io: Spring Web, Data JPA, Validation, H2, Flyway,
       Actuator, DevTools; mais springdoc-openapi-starter-webmvc-ui. Pacote
       base br.com.clxj.tracker.
     - Package by feature: cliente, projeto, discovery (requisitos, tarefas),
       delivery (itens, subtarefas, histórico, board), dashboard, shared (erros,
       config).
     - Entidades JPA + repositórios; DTOs como record; validação com Bean
       Validation e mensagens em pt-BR (ValidationMessages.properties).
     - Erros via @RestControllerAdvice retornando ProblemDetail (RFC 9457).
     - Schema via Flyway (db/migration/V1__schema.sql) mesmo com H2 in-memory —
       facilita trocar para Postgres depois. Seed de dados de exemplo em perfil
       dev (V100__seed_dev.sql ou CommandLineRunner).
     - H2 console habilitado em dev (/h2-console). Swagger UI em
       /swagger-ui.html.
     - Endpoints principais (/api/...):
       - clientes, projetos (CRUD, filtros por status/cliente)
       - projetos/{id}/requisitos, projetos/{id}/tarefas (CRUD, filtros
         tipo/status/prioridade)
       - tarefas/{id}/enviar-para-delivery
       - projetos/{id}/board (itens agrupados por status, com idade calculada)
       - itens/{id} (CRUD), itens/{id}/mover (status + ordem; registra histórico
         e inicioWip), itens/{id}/impedimento (PUT marcar com motivo / DELETE
         remover), itens/{id}/subtarefas
       - dashboard (contagens por projeto/status/tipo de requisito, itens
         impedidos, top itens mais antigos em WIP)
     - Lógica de transição/aging isolada em delivery/WorkflowService (fácil de
       testar; usa Clock injetado).
     - Testes: JUnit 5 + AssertJ; @DataJpaTest (repositórios), @WebMvcTest
       (controllers), testes unitários do WorkflowService (aging, impedimento,
       histórico), um @SpringBootTest de fumaça.

     Frontend (frontend/)

     - create-next-app (Next.js mais recente, App Router, TypeScript, Tailwind
       v4, ESLint) + shadcn init com componentes: button, card, dialog, sheet,
       form, input, textarea, select, badge, table, tabs, dropdown-menu, sonner,
       sidebar, chart.
     - Toda a UI em pt-BR (<html lang="pt-BR">, date-fns/locale/ptBR, rótulos de
       enums mapeados em lib/labels.ts).
     - Integração com API: rewrite no next.config.ts (/api/:path* →
       http://localhost:8080/api/:path*), evitando CORS. Tipos TS espelhando os
       DTOs em lib/types.ts; cliente em lib/api.ts.
     - Dados: TanStack Query; formulários: react-hook-form + zod; drag-and-drop
       do Kanban: @dnd-kit/core + @dnd-kit/sortable (com atualização otimista).
     - Rotas:
       - / Dashboard (cards de KPIs + gráficos shadcn/Recharts)
       - /clientes, /clientes/[id]
       - /projetos, /projetos/[id] com abas Visão geral · Discovery · Delivery
         - Discovery: tabela de requisitos (filtros tipo/status/MoSCoW) e lista
           de tarefas com ação "Enviar para Delivery"
         - Delivery: board Kanban de 9 colunas (scroll horizontal), card com
           título, progresso de subtarefas (x/y), badge de aging, indicador de
           impedido; Sheet lateral para detalhes, subtarefas e histórico de
           status
     - Layout com Sidebar do shadcn, tema claro/escuro.

     Fases de execução

     1. Setup: verificar/instalar JDK 25 e Node 24; git init, .gitignore,
        README; gerar backend e frontend; ambos sobem "vazios".
     2. Backend Clientes + Projetos (entidades, migração, API, testes).
     3. Backend Discovery (requisitos, tarefas, enviar para Delivery).
     4. Backend Delivery (itens, subtarefas, mover, impedimento, histórico,
        aging, board) + Dashboard.
     5. Frontend base (layout, sidebar, cliente de API, labels pt-BR) + telas
        Clientes/Projetos.
     6. Frontend Discovery.
     7. Frontend Delivery (Kanban com dnd-kit, impedido, aging, sheet de
        detalhes).
     8. Frontend Dashboard + seed de dados de exemplo + CLAUDE.md com comandos
        do projeto.

     Verificação

     - cd backend && ./mvnw verify — todos os testes passam.
     - ./mvnw spring-boot:run → Swagger em http://localhost:8080/swagger-ui.html
       e exercitar endpoints; H2 console para inspecionar dados.
     - cd frontend && npm run lint && npm run build; npm run dev →
       http://localhost:3000.
     - Fluxo ponta a ponta no navegador: criar cliente → projeto → requisitos
       RF/RNF → tarefa → "Enviar para Delivery" → arrastar item pelas colunas →
       marcar/desmarcar impedido → conferir badge de aging (usando seed com
       datas retroativas) e histórico → dashboard reflete as contagens.
